The RTL schematic generated by Xilinx Vivado shows the 
complete hierarchical structure of the 16-bit ALU. 

**Key observations:**
- **LU** (Logic Unit) — handles AND, OR, XOR, NAND, NOR, XNOR, NOT
- **AU** (Arithmetic Unit) — handles ADD, SUB, INC, DEC
- **SU** (Shift Unit) — handles LSL, LSR, ROL, ROR
- **MUX** — selects correct output based on group_sel
- All sub-modules compute simultaneously in hardware
- Opcode decoder (RTL_LEQ, RTL_SUB) on left side
- 4 flag outputs visible on right side

- ## RTL Schematic — Arithmetic Unit
<img width="1547" height="705" alt="ss_AU" src="https://github.com/user-attachments/assets/95373fa6-56b5-4b4a-8d45-5282405a6547" />
Internal view of arithmetic_unit sub-module showing:
Internal view of `arithmetic_unit.v` sub-module showing
ADD, SUB, INC, DEC operations with carry capture logic.

| arith_op | Operation | Expression | Uses B? |
|----------|-----------|------------|---------|
| 00 | ADD | A + B | Yes |
| 01 | SUB | A - B | Yes |
| 10 | INC | A + 1 | No |
| 11 | DEC | A - 1 | No |

**Key observations:**
- 17-bit `temp` register used instead of 16-bit to capture
  carry bit — `{1'b0, A} + {1'b0, B}` prevents carry loss
- Separate datapaths for ADD, SUB, INC, DEC operations
- `temp[16]` = carry output, `temp[15:0]` = actual result
- INC and DEC ignore operand B — only A is used
- `carry_out` is the only flag driven by this sub-module
- Default `carry_out = 0` before case statement
  prevents unintentional latch inference

Internal view of `logic_unit.v` showing all 7 bitwise operations
implemented as parallel hardware gates.:

| logic_op | Operation | Expression |
|----------|-----------|------------|
| 000 | AND | A & B |
| 001 | OR | A \| B |
| 010 | XOR | A ^ B |
| 011 | NAND | ~(A & B) |
| 100 | NOR | ~(A \| B) |
| 101 | XNOR | ~(A ^ B) |
| 110 | NOT | ~A (B ignored) |

 **Key observations from schematic:**
- All 7 operations implemented as parallel hardware gates
- Basic gates: AND (&), OR (|),NOT(~)
- NAND and NOR are universal gates — any circuit can be
  built from NAND alone
- NOT only uses operand A — B is ignored
- RTL_MUX block at output selects correct result
  based on logic_op


## RTL Schematic — Shift Unit
<img width="1746" height="665" alt="ss_SU" src="https://github.com/user-attachments/assets/f103547c-ba69-4415-bdaf-d12437efd0e5" />
Internal view of `shift_unit.v` showing 4 shift operations.
Only operand A is used — B is not needed for shifting.

| shift_op | Operation | Expression | Bits Lost? |
|----------|-----------|------------|------------|
| 00 | LSL | A << 1 | Yes — MSB lost |
| 01 | LSR | A >> 1 | Yes — LSB lost |
| 10 | ROL | {A[14:0], A[15]} | No — wraps around |
| 11 | ROR | {A[0], A[15:1]} | No — wraps around |
 
Note: Only A is used — B is not needed for shift operations

**Key observations from schematic:**
- Only operand A is used — port B is not connected
  to shift_unit (shift amount is fixed at 1 bit)
- LSL: A << 1 (MSB lost, LSB filled with 0)
- LSR: A >> 1 (LSB lost, MSB filled with 0) 
- LSL and LSR lose one bit per shift — used for
  multiply/divide by 2
- ROL: {A`[14:0]`, A`[15]`} (MSB wraps to LSB — no bits lost)
- ROR: {A`[0]`, A`[15:1]`} (LSB wraps to MSB — no bits lost)
- ROL and ROR use bit concatenation to wrap bits
  around — no data is lost — used in cryptography
- 2-bit shift_op is sufficient for 4 operations
  (2² = 4) — no 3rd bit needed unlike logic_unit

## RTL Schematic — MUX Unit

Internal view of `mux_unit.v` — selects correct output
from all 3 simultaneously computed results.

| group_sel | Selected Output | Group |
|-----------|-----------------|-------|
| 00 | arith_result | Arithmetic |
| 01 | logic_result | Logic |
| 10 | shift_result | Shift |
| 11 | 16'b0 | Default (zero) |

- All 3 units always compute simultaneously.
- MUX only selects which result to forward — exactly
- how real CPU ALU designs work.
